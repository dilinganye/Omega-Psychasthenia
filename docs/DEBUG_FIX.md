# 精神创伤模组：实现与文档差异审查

审查日期：2026-09-12

本文只记录当前源码、数据表和现有说明之间的不一致、尚未闭环的实现与需要实机确认的风险。本轮没有修改游戏逻辑。`docs/INVATION_IDEAS.md` 与 `docs/NEWS_TRUE_SITE_IDEAS.md` 已明确声明是设计池，因此其中尚未实现的构想不单独视为缺陷。

## 结论摘要

当前 DORMANT 90 日、RECON 365 日的阶段时长已经落入代码，暗流、火力侦察、侦察舰队、新闻调查、Je、局部恐慌和战略事件也都已有可运行骨架。但现状存在 4 项应优先处理的确定性问题：

1. 塔罗弹体仍直接请求曾在实机中报错的 `dweller/dweller_pieces` 纹理。
2. HUD 新闻条实现存在，但唯一正常触发调用被注释，功能实际上没有接入。
3. Je 的“前期减恐慌加成”方向反了，前期反而比后期消除得更少。
4. 新闻对攻击权重的即时影响会被周期性权重重算覆盖，事件无法形成持久战略记忆。

此外，CUSTOM 新闻的全局 `advance()` 接口没有调用点，侦察评分仍有全知信息来源，Dev 事件条件与文档不完全相符，部分测试文档保留了旧版本口径。

## A. 确定性缺陷

### A-01　塔罗 Shroud 肢体团仍可能触发缺失纹理崩溃

- 优先级：P0
- 证据：`PTSD_TarotProjectileEffect.createShroudedLimbGroup()` 固定设置 `spriteCat = "dweller"`、`spriteKey = "dweller_pieces"`。
- 已知现象：项目历史测试已出现 `Texture [dweller_pieces] from category [misc] not found`；当前实现虽然改成了 `dweller` 分类，但没有运行时能力探测或安全回退。
- 文档冲突：`TAROT_WEAPON_TESTING.md` 将原版肢体团描述为稳定可用能力。
- 影响：任何被抽中创建肢体团的弹体都可能在资源未注册的环境中直接终止战斗。
- 建议：加载时验证 sprite；失败时永久关闭本局肢体团路径并回退到普通塔罗粒子。不要只依赖异常捕获，因为纹理错误可能发生在原版效果的延迟渲染阶段。

### A-02　HUD 新闻条没有接入新闻创建路径

- 优先级：P1
- 证据：`PTSDNewsTicker` 类、`install()`、`report()` 均存在；但 `PTSDCrisisIncidentManager.createIncident()` 中唯一的 `PTSDNewsTicker.report(incident)` 被注释，项目内没有其他安装或调用位置。
- 文档冲突：`DEV_CRISIS_TESTING.md` 第 20 节称每次新闻创建都会在右下角显示约 13 秒。
- 影响：玩家不会收到预期的生涯 HUD 滑动新闻；右键快捷进入新闻 Intel 也无法使用。
- 备注：源码注释写明因字体问题关闭，而测试文档仍把它视为已完成，两者必须统一。

### A-03　Je 的前期恐慌缓解倍率方向反转

**状态：已修复（2026-09-12）。** 前期倍率现在除以“剩余影响比例”；玩家实地调查与 Je 代查均会在前期消除更多恐慌。

- 优先级：P1
- 证据：`getEarlyPanicMitigationBonus()` 在前期返回最高约 `1.65`；`mitigateIncident()` 的参数语义却是“剩余比例”，比例越大，消除越少。
- 玩家实地任务：当前传入 `0.5 * bonus`，前期约保留 82.5%，仅消除 17.5%；后期保留 50%，反而消除 50%。
- Je 代查：随机 5%–75% 又乘以前期 bonus，同样提高了剩余比例，严重时可保留到 95%。
- 文档冲突：`DEV_CRISIS_TESTING.md` 第 21 节明确称前期有额外缓解，随后衰减到 1.0。
- 建议：明确区分 `remainingRatio` 与 `removalRatio`；前期加成应降低剩余比例，或提高移除比例。UI 中展示的百分比也必须明确表示“剩余影响”而不是“已消除影响”。

### A-04　新闻事件的攻击权重影响会被下一次重算抹除

**状态：已修复（2026-09-12）。** 新增持久 `incidentWeightBias` 并在每次权重重算后作为输入应用，同时建立对应 `EvidenceRecord`。

- 优先级：P1
- 证据：`PTSDCrisisIncidentManager.applyEffects()` 直接执行 `data.attackWeight *= ...`；`IIRT_Omega_Invasion.updateSystemWeights()` 随后从防御、价值、置信度等重新赋值 `data.attackWeight = ...`。
- 文档冲突：暗流/火力侦察说明将若干事件描述为提高目标权重；危机进度文档也称事件进度参与攻击权重。
- 影响：D/P 新闻的“战略影响”通常只存在到下一次权重更新，无法成为后期进攻学习的一部分。
- 建议：新增持久的 `incidentWeightBias`、情报标签或证据贡献表，重算时把它作为输入；不要再直接修改派生结果。

### A-05　CUSTOM 新闻的全局 advance 接口未被调用

**状态：已修复（2026-09-12）。** 新闻 heartbeat 现在调用已加载 handler；同一实例注册多个别名时按对象身份去重。

- 优先级：P1
- 证据：`PTSDCrisisNewsAPI.advanceLoadedHandlers()` 已实现，但全项目没有调用点。
- 文档冲突：`NEWS_EXTENSION_API.md` 承诺已加载 handler 会在每个危机 heartbeat 收到 `advance(AdvanceContext)`。
- 影响：第三方模组依照公开接口编写的长期新闻效果不会运行；内置逃犯事件若未来依赖此接口也会静默失效。
- 建议：在新闻管理器 heartbeat 中只调用一次，并记录上次推进日，避免多个别名指向同一对象时重复推进。

### A-06　侦察评分仍混入全知信息

**状态：已修复（2026-09-12）。** `SystemData` 已拆分真实快照、欧米伽认知与证据。正式攻击选点只接受已被证据确认存在殖民地的星系。

- 优先级：P1（设计正确性）
- 证据：`updateSystemWeights()` 每轮直接遍历所有星系的实时舰队和市场，读取实际舰队 FP、市场规模、稳定度、工业与空间站；没有侦察历史时还会用实时 `fleetDefense` 反推 `observedFleetStrength`。
- 文档/设计冲突：现有说明强调侦察舰提交每日最高样本，并由侦察建立后期攻击权重。当前系统即便从未派舰抵达，也知道殖民地是否存在、真实工业和实时舰队的一部分。
- 影响：玩家无法通过隐藏调动、假编成、摧毁观测节点或制造错误情报真正欺骗欧米伽；“聪明”表现更接近读取全图数据。
- 建议：拆成 `groundTruth`（仅供结算/Dev）、`omegaBelief`（只由观察更新）和 `confidence/lastSeen`。正式选目标只读 belief；低置信时允许有偏差。

### A-07　危机信号相关器会泄露未记录新闻的位置

**状态：已修复（2026-09-12）。** 相关器只显示已经物化的战略实体，以及玩家已记录且现场已经物化的新闻实体。

- 优先级：P1
- 证据：`PTSDCrisisDetectorAbility.collectTargets()` 遍历所有未解决 incident，不检查 `recordedByPlayer`、`disclosed` 或 `siteMaterialized`；在超空间中会把其目标星系锚点加入方向标记。
- 文档冲突：说明将其描述为指向已生成的危机实体和调查目标，而非揭示所有后台新闻真坐标。
- 影响：开启能力后，玩家可能获得从未查看或记录的新闻精确方向，也会把假消息后台目标当成真实危机信号。
- 建议：只显示已记录调查、已物化现场、已目击舰队与明确标记为可探测的实体；假消息可显示模糊噪声，但不应给精确锚点。

## B. 事件与阶段实现未闭环

### B-01　RECON 每日事件不受公开频率设置与探测器倍率影响

- `PTSDReconPlayerEvents.rollDaily()` 使用固定 1%/2%/3%/5%/2% 概率。
- `未知事件频率`、触发上下限和相关器的 1.45 倍会影响新闻、普通侦察舰和若干战略调度，但不会影响这五项每日事件。
- 文档称这些设置统一控制“各种事件触发频率”，容易形成错误预期。
- 建议：明确每日概率是否属于统一频率域；若属于，应使用同一倍率并设置单日总上限。

### B-02　火力侦察事件不根据实体战斗结果形成反馈

**状态：已修复（2026-09-12）。** 现区分完成采样、接触后逃逸、被迫中断、被摧毁，并分别回写证据与危机变量。

- `FIRE_PROBE` 到期时被统一标为成功，当前没有像正式 ATTACK 那样根据舰队被消灭、撤退或玩家介入更新结果。
- 因此玩家击毁火力试探舰队不会自然反向影响该事件的置信、攻击性、对抗值或后续编成。
- 建议：为 `FIRE_PROBE` 增加“完成采样 / 被迫中断 / 全灭 / 成功逃逸”四类结算，并写入对应势力及玩家的反制画像。

### B-03　侦察舰切换邻近星系时没有复用初始目标过滤

**状态：已修复（2026-09-12）。** 换区排除隐藏、切断超空间、已占领和无目标星系，并在最多八个邻近候选中重试。

- 初始选址会排除 `SYSTEM_CUT_OFF_FROM_HYPER`，部分路径还排除隐藏星系。
- `IIRT_Omega_ScoutAI.switchToNearbySystem()` 只按距离选择最近星系，没有过滤隐藏、切断超空间、危机已占领或无有效落点的星系，也没有 8 次重试保护。
- 影响：连续五日空样本后的换区可能进入不可达/不应公开的系统，或让侦察任务在路径上卡住直到 120 日 failsafe。

### B-04　“安全落点”仍有未经复检的兜底位置

**状态：已修复（2026-09-12）。** 新增统一严格安全点 API；新闻现场、战略投影、残骸和侦察期玩家事件找不到安全点时取消生成。

- 新闻现场与战略残骸会尝试多次避开恒星、黑洞、行星和跳跃点，但失败后的最终 fallback 不再完整复检。
- `PTSDReconPlayerEvents` 的航路残骸和若干玩家周边生成也主要按方向/半径放置，没有统一调用安全落点工具。
- 文档把“不会生成在碰撞箱内”写成确定保证，实际应改为“高概率规避，兜底仍有风险”，或统一到一个严格的安全点 API。

### B-05　侦察事件对权重的贡献缺少可解释的持久明细

**状态：已修复（2026-09-12）。** 每星系保存最多 64 条有期限的 `EvidenceRecord`，记录来源、观测、可信度、过期日和玩家干扰。

- 系统只保存最终 `attackWeight`、若干日样本和计数，无法回答某星系为何被判为薄弱：是通讯基站样本、舰队空窗、市场防御、玩家追逐，还是某条新闻造成。
- 这会限制后续战区 Intel、Je 反情报任务和 Dev 调试。
- 建议：每星系保存有期限的 `EvidenceRecord` 列表，含来源、观测值、可信度、衰减日、是否被玩家污染。

### B-06　365 日侦察的自然进度会过早封顶

- RECON 每日自然增加 `RECON_CONFIDENCE +0.35`，阶段进入时又至少为 15。
- 不计算任何事件和侦察舰，仅约 243 日就会达到 100；余下约 122 日继续等待，侦察行为对总置信的边际价值消失。
- 同时火力侦察通常会因置信达到 36 在约 60 日便开启，使“42% 阶段时长”的备用门槛多数情况下不起作用。
- 建议：自然增长改为软上限或只增长“推演预算”；真正置信由覆盖率、样本新鲜度和多域完成度决定。

### B-07　DORMANT 目前主要是新闻等待，没有独立战略状态

- DORMANT 除暗流卡和极低自然侦察增长外，没有独立的隐蔽度、渗透网络、观察节点或玩家反制资源。
- 90 日内容可见度高度依赖 3–7 日新闻抽取，玩家对阶段长度几乎没有影响。
- 这不是代码错误，但与“暗流涌动、可延缓战争、为后期制衡做准备”的目标仍有明显距离。

### B-08　属实现场的 32 种差分目前多为“名称+通用实体组合”

- `PTSDNewsSiteManager` 已为 32 个标题和描述建立六类实体化外壳，这是有效的第一版。
- 但 `NEWS_TRUE_SITE_IDEAS.md` 中诸如延迟复现、动态改写求救信号、循环三秒、武器响应裂纹等独特确认逻辑尚未实现；统一确认仍是抵近约 1800 距离。
- 该文档已经声明是规划，因此不算违约；后续不应把“已拥有 32 个名字”误认为“32 个玩法现场均已完成”。

## C. DevMode 与测试入口偏差

### C-01　专项调查 JE-01 可绕过 Je 前置条件显示和触发

- `getDevCardsForCurrentPhase()` 会返回所有 phase 匹配卡，包括 `phases=ALL` 的 `JE-01`。
- Dev 控制台随后为每张卡生成 `NEWS:<id>` 按钮，`force()` 不检查 Je 是否解锁或初次事件是否完成。
- 文档却称条件不满足的后续事件不会显示且无法越权触发。
- 建议：为 CSV 增加 `devGate`/`triggerGroup`，或至少从通用卡列表排除“专项调查”。

### C-02　Je 任务按钮没有把 12 日冷却作为显示条件

- `JE_PLAYER`、`JE_AGENT` 在满足联系人基础状态时显示，但未检查 `canStartAnotherTask()`。
- 点击后 manager 返回 `null`，界面没有失败说明，表现为按钮无反应。
- 建议：冷却中隐藏按钮，或显示禁用按钮和剩余天数；Dev 的“刷新任务状态”按钮保持可用。

### C-03　强制新闻接口本身不校验阶段

- UI 默认只枚举当前 phase，但 `force(cardId)` 可直接强制任意卡。
- 对真正的 Dev API 这可能是有意行为；需要把文档改成“UI 遵守阶段，代码级 force 明确忽略阶段”，不要宣称旧按钮 ID 无法越权触发。

### C-04　Dev 监视器会隐藏自然日增量，但缺少侦察信念来源分解

**状态：已修复（2026-09-12）。** 权重 Intel 和监视器显示认知/真实防御、误差、置信、事件偏置与最近证据明细。

- 当前能看到最终攻击权重、日最大样本和事件记录，但不能查看观测值、真实值、置信区间、衰减和事件偏置。
- 在将评分改成非全知模型前，Dev UI 应先规划“真实/认知/误差”三列，否则很难验证欧米伽是否真的学聪明。

## D. 文档漂移与相互矛盾

### D-01　`DEV_CRISIS_TESTING.md` 同时保留两套战略投影时长

- 旧段落称舰队投影约 2.5 日、残骸约 5 日。
- 第 19 节称离开范围 10 日后卸载、战后遗迹 60 日。
- 当前代码采用后者：离开 10 日卸载，战后投影窗口与残骸约 60 日；`projectionExpiresDay = +10` 字段并未作为旧 2.5 日规则使用。
- 应删除或明确标注旧段落。

### D-02　危机状态版本号说明过时

- 测试文档仍称旧存档迁移到版本 6。
- `PTSDCrisisState.CURRENT_VERSION` 当前为 10；版本 10 增加星系证据/认知字段与火力试探结果迁移。

### D-03　塔罗稳定器存在两份互相冲突的规则说明

- `TAROT_WEAPON_TESTING.md`：每次命中触发、消耗全部层数。
- `WEAPON_VISUAL_REWORK_TESTING.md` 与当前代码：5% 概率触发、消耗一半层数。
- `weapon_data.csv` 的旧说明也需要与最终规则统一。

### D-04　新闻 CSV 路径在文档中不统一

- 实际路径：`data/config/ptsdCSV/PTSD_crisis_news.csv`。
- `NEWS_EXTENSION_API.md` 使用正确路径。
- `CRISIS_PROGRESS_API.md` 和 `PTSDCrisisNewsAPI` 类注释仍写 `data/config/PTSD_crisis_news.csv`。
- 第三方扩展者若照错路径放表，将无法被当前 loader 读取。

### D-05　新闻数量说明少计专项调查

- 当前 CSV 有 68 条有效记录：12 暗流、12 火力侦察、21 普通/势力新闻、6 扩张、6 封锁、10 战争、1 专项调查。
- `DEV_CRISIS_TESTING.md` 只写 67 条，没有说明额外的 `JE-01`。

### D-06　旧 `deas!` 文档不再适合作为实现依据

- 多份文件仍写 DORMANT 65 日、RECON 60 日、旧阶段枚举和旧 Luna 参数。
- 当前源码默认值为 90/365/30/30，正式阶段枚举为 DORMANT/RECON/EXPANSION/FORTIFICATION/WAR/ENDED。
- 建议给 `deas!` 加总入口 README，明确“历史归档，不用于验收”，或移动到 `docs/archive/`。

### D-07　暗流文档仍使用“公众恐慌”旧称

- D-04/D-09 等说明写公众恐慌；当前实现写入的是以事件地点为中心的殖民地局部恐慌。
- `GLOBAL_PANIC` 当前确实不会被普通新闻修改，这一点代码与新危机 API 文档一致。

### D-08　新闻条字体说明与代码状态矛盾

- `PTSDNewsTicker` 内注释声称 `orbitron20aabold.fnt` 包含当前中文字符。
- 事件管理器旁注却称字体“烂完了”并关闭调用。
- 在重新启用前需要明确：使用原版中文 UI 字体、预渲染字形、位图标题，还是只显示 ASCII 分类并由 Intel 展示中文。

## E. 低优先级代码与扩展风险

### E-01　分支舰表含有放错容器或无效的 wing ID

- `TranvariantData` 的 FRIGATE `GENERAL` 中混入若干 `_wing` ID，另有几行把 Record wing 再写回 `fighters` 而不是 `small`。
- 当前生成器用 `doesVariantExist()` 过滤，通常不会把 LPC 当舰船生成，因此暂不构成直接崩溃；但会降低候选有效率并掩盖录入错误。

### E-02　分支生成并未完全使用调用方传入的 Random

- 舰体等级选择使用传入 `Random`，但 `pickVariantForSize()` 内使用 `Math.random()`。
- 影响：相同 seed 无法复现同一编成，Dev 重放、事件确定性和未来存档调试较困难。

### E-03　Generic scene 的清理语义需要统一说明

- 新闻现场清理会跳过 WRECK 和 terrain，让它们依靠自身 duration 消失；其他节点在确认后 1–5 日移除。
- 这与“动态实体快速清理、残骸长期保留”的目标基本一致，但 `siteEntityIds` 清空后不再能由新闻系统主动回收被跳过的残骸。
- 若后续自定义 handler 需要强制清理，需提供“保留实体”和“必须删除实体”两组 ID。

### E-04　大量宽泛 Throwable 捕获会把功能失败降格成静默缺失

- 新闻实体、残骸、舰队、CUSTOM handler 等多处会捕获全部 Throwable 后继续。
- 这有利于避免整局崩溃，但玩家端可能只看到空现场或按钮无反应。
- 建议至少在 DevMode 统一汇总“降级执行”计数和最后异常，而不是只写日志。

## F. 建议的修复顺序

1. P0：塔罗纹理能力探测与安全回退。
2. P1：修正 Je 恐慌倍率语义；恢复或正式移除 HUD 新闻条。
3. P1：把新闻权重影响改为持久证据；接通 CUSTOM `advance()`。
4. P1：拆分真实战略数据与欧米伽认知数据，封堵信号相关器的信息泄露。
5. P2：修正 Dev 条件、侦察换区过滤、统一安全落点。
6. P2：合并测试文档的旧新口径，并把 `deas!` 标为归档。
7. P3：清理舰表误项、统一 Random、补充降级可视化。

## G. 建议的实机验证清单

- 连续发射所有塔罗武器 5 分钟，确认不请求缺失纹理且肢体团预算能回落。
- 强制生成一条中文新闻，确认 HUD 条出现、文字非问号、右键只打开目标 Intel。
- 分别在低/高准备度完成相同 Je 任务，记录事件恐慌的前后值，验证前期消除更多。
- 强制 D/P 事件，推进越过一次权重更新，确认事件偏置仍存在。
- 注册测试 CUSTOM handler，记录 `pick/onCreated/advance` 三类调用次数。
- 开启相关器但不记录新闻，确认不会显示未公开目标；记录后才出现方向提示。
- 让侦察舰连续五日空采样，确认换区不会选择隐藏或切断超空间星系。
- 在高模组星系数量环境快速推进 60 日，统计活动危机舰队、新闻现场、残骸和海盗上限。
