# 精神创伤危机：DevMode 观察与触发指南

> 暗流 D-01～D-12、火力侦察 P-01～P-12、LunaLib 公开/Dev 设置及阶段开关的最新说明见 [DARK_CURRENT_FIRE_PROBE.md](DARK_CURRENT_FIRE_PROBE.md)。

本文用于验证 `Omega_PTSD_Invasion` 的阶段推进、侦察、扩张、要塞化和全面战争。所有 `[DEV]` 内容只在 Starsector DevMode 开启时存在；关闭 DevMode 后，调试监视器和仅为调试补建的 Intel 会自动移除，正常的“偶然目击—逐步揭示”逻辑不受影响。

## 1. 进入监视器

1. 用项目当前采用的方式开启 Starsector DevMode，然后载入存档或按 F8 重载脚本。
2. 打开 Intel 界面，找到 **`[DEV] 精神创伤危机监视器`**。
3. 监视器顶部显示：
   - 当前内部阶段和已经持续的天数；
   - 玩家正常可见阶段；
   - 接触、侦察目击和逃脱次数；
   - 下一次侦察、权重更新、扩张、要塞、Omega 回合和人类回合的相对倒计时；
   - 核心基地、两级警告和第四窥视资产移交状态；
   - 攻击权重最高的十个星系。
4. “战略事件”区显示远方隐藏推演事件和已实体化事件；“即时触发记录”区显示阶段切换、侦察生成、警告、改造、要塞等瞬时动作。

每条有有效位置的事件都有两个按钮：

- **前往**：调用原版 `SectorAPI.layInCourseFor()`，为玩家舰队铺设前往目标的航线。
- **到达**：把玩家舰队转移到目标所在 Location，并放置在目标附近。该操作会真实触发“玩家靠近后实体化”、侦察目击等距离逻辑。

“直接访问情报”中的两个按钮可在 DevMode 下打开战前危机 Intel 和战区态势 Intel。若剧情尚未正常解锁，它们带有 `[DEV预览]` 前缀；若随后满足正式解锁条件，预览会原位升级为正式 Intel。

## 2. 推荐的 LunaLib 测试参数

在 LunaLib 的模组设置中缩短以下参数，可快速跑完一个测试周期：

| 设置 ID | 建议测试值 | 用途 |
| --- | ---: | --- |
| `PTSD_start_stage_time` | 90 | DORMANT → RECON |
| `PTSD_collect_data_time` | 365 | RECON → EXPANSION |
| `PTSD_invade_time` | 5 | EXPANSION → FORTIFICATION |
| `PTSD_repair_time` | 5 | FORTIFICATION → WAR |
| `PTSD_scout_min_interval` | 1 | 侦察最短刷新间隔 |
| `PTSD_scout_max_interval` | 2 | 侦察最长刷新间隔 |
| `PTSD_scout_max_active` | 3 | 同时存在的侦察舰队上限 |
| `PTSD_warning_encounter_threshold` | 1 | 一次有效接触即可触发软警告 |
| `PTSD_strategic_update_interval` | 1 | 权重表更新间隔 |
| `PTSD_expansion_interval` | 3 | 行星扩张改造间隔 |
| `PTSD_front_turn_min_interval` | 2 | 战线回合最短间隔 |
| `PTSD_front_turn_max_interval` | 3 | 战线回合最长间隔 |
| `PTSD_hidden_materialization_range` | 10000 | 便于观察隐藏事件实体化 |

`PTSD_DefStat_onNewGame` 可让**新游戏**从指定阶段开始：

| 值 | 阶段 |
| --- | --- |
| `Sar` | DORMANT / 起始等待 |
| `Cod` | RECON / 侦察 |
| `Inv` | EXPANSION / 建设扩张 |
| `Rep` | FORTIFICATION / 要塞化 |
| `FuA` | WAR / 全面进攻 |
| `End` | ENDED / 结束 |

现有存档应以监视器中的“当前阶段”为准；改变新游戏默认阶段不会倒写已有危机状态。

## 3. 各事件的触发与观察目标

| 事件 | 触发办法 | DevMode 中应看到 | 发展状态应发生的变化 |
| --- | --- | --- | --- |
| 阶段切换 | 等待对应阶段计时结束；测试时缩短四个阶段时间 | 即时记录“阶段切换”，顶部阶段和阶段开始日更新 | 下一类阶段计时被初始化 |
| 侦察舰队启航 | 进入 RECON，等待 `nextScoutDay`；保证活动侦察数低于上限 | 记录任务类型、目的地、驻留天数和远端生成的舰队；可对舰队使用前往/到达 | 此时仅进入 `TRAVEL`，不会提前增加 `scoutVisits` 或消耗驻留时间 |
| 侦察抵达任务区 | 跟踪启航记录，或等待舰队自行完成跨超空间航行 | “侦察任务阶段：抵达任务区”；可见 `$PTSD_scout_mission` 与 `$PTSD_scout_stage` | 抵达后才增加 `scoutVisits`，并开始 `OBSERVE/ROAM` 驻留计时 |
| 侦察被目击 | 点击侦察记录的“到达”，让侦察进入玩家可见范围 | “侦察单位被目击”记录 | `totalScoutSightings`、`totalOmegaEncounters` 和该星系目击数增加 |
| 侦察撤离/逃脱 | 靠近或追逐侦察舰队，等待其逃离并消失 | “侦察单位脱离”记录 | `totalScoutEscapes` 增加；若摆脱玩家，异常接触数也增加 |
| 软警告 | 让有效接触数达到 `PTSD_warning_encounter_threshold` | “软警告触发”；战前 Intel 正式出现 | `softWarningShown=true`，玩家正常可见阶段提升 |
| 核心据点建立 | 进入 EXPANSION；系统首次执行 `ensureBase()` | “核心据点建立”，可直接到达被改造行星 | `baseSystemId/baseMarketId` 写入；Omega 控制=1；行星大幅改造 |
| 行星扩张改造 | EXPANSION/FORTIFICATION/WAR 中等待 `nextExpansionDay` | “行星扩张改造”，显示行星和改造等级 | 目标星系 `conversionLevel` 递增；产生建设事件 |
| 黑洞要塞建立 | 进入 FORTIFICATION/WAR，等待 `nextFortressDay`；确保要塞数未达上限 | “黑洞要塞建立”，可到达空间站附近 | `blackHoleFortress=true`；Omega 控制=1；产生要塞巡逻事件 |
| 战略事件生成 | 建设、卫戍、要塞巡逻、Omega 进攻、人类防御、佣兵、玩家舰队或外部 API 排队 | “战略事件生成”；监视器显示类型、阵营、强度、目标和结算日 | 事件进入 `PLANNED` |
| 隐藏事件实体化 | 点击某战略事件“到达”，或正常进入其物化距离 | “战略事件实体化”，按钮优先跟踪实际舰队 | 状态 `PLANNED → MATERIALIZED`，写入 `materializedFleetId` |
| 实体卸载 | 离开目标星系/物化范围，且事件未临近结算、舰队未交战 | “战略事件卸载” | 保存剩余强度，状态回到 `PLANNED`，远方继续隐藏推演 |
| 全面入侵警告 | 进入 WAR（正常流程最终必然发生） | “全面入侵警告触发”；第四窥视资产移交；战区 Intel 正式出现 | `hardWarningShown=true`、`watcherTransferred=true` |
| Omega 战线回合 | WAR 中等待 `nextOmegaTurnDay` | 新的 ATTACK 战略事件和相应目标位置 | 按侦察权重优先选择薄弱点 |
| 人类战线回合 | WAR 中等待 `nextHumanTurnDay` | DEFENSE / MERCENARY_DEFENSE 等事件 | 按人类防御权重部署，受大局上限和玩家标记影响 |
| 战略事件结算 | 等待 `resolveDay`，或在实体化后摧毁相应舰队 | “战略事件结算”，显示成功/失败 | 事件进入 `RESOLVED`；进攻结果更新学习倍率、控制权和后续建设 |
| 殖民地摧毁与占领 | 让 Omega ATTACK 成功结算 | 后续建设、卫戍事件出现在监视器 | 殖民地被摧毁并划为精神创伤实控区；目标行星进一步改造 |
| 玩家特化舰队 | WAR Intel 中使用殖民地产能组建舰队 | PLAYER_TASK_FORCE 事件 | 最多 8 支；占用产能并以独立部署权重影响战线 |
| 外部模组干涉 | 由其他模组调用 `PTSDCrisisAPI.queueExternalEvent()` 或注册 provider | EXTERNAL 事件、外部兵力标记/权重变化 | 进入统一隐藏事件列表并参与战线结算 |

### 侦察任务类型与预期轨迹

| 内部类型 | 目标与行为 | 正常结束条件 |
| --- | --- | --- |
| `RELAY` | 从超空间远端启航，前往通讯基站，抵达后静默扫描 4–12 日 | 驻留结束后沿远端航线撤离 |
| `HYPERSPACE_WATCH` | 前往目标星系外的超空间监听点，驻留约 16–44 日 | 任意非友军舰队靠近或计时结束后撤离 |
| `COLONY_INFILTRATION` | 目击数达到门槛后才加入抽选，潜入非 Omega 殖民地外层 | 被巡逻队指定拦截、近距离接触或驻留结束后撤离 |
| `WILDERNESS_ROAM` | 前往没有正常殖民地的星系，在行星、跳跃点和中心间游走约 24–60 日 | 漫游计时结束后撤离 |

- 每次刷新最多重选 8 个任务目标。候选目标或其他模组实体抛出异常时，只记录警告并改选；全部失败则两日后重试。
- `TRAVEL` 最长保留 120 日，航行期间不会因生成时间过久被判定完成。旧存档中的旧式侦察 AI 会迁移到同一状态机。
- 玩家尚未看见侦察舰队时，玩家距离不会触发逃跑。可见后，近距离靠近、距离持续缩短或以其为指派目标会触发 `ESCAPE`。
- 撤离舰队会向远离威胁的超空间远点航行；离开玩家视野并拉开足够距离后消失。舰队带有禁止回收与无残骸标记。
- Dev 监视器会记录“启航、抵达任务区、被目击、脱离、完成撤离/失效”等阶段，并保留舰队 ID 供“前往/到达”定位。
## 4. 一次完整验收流程

1. 开启 DevMode，载入测试档，确认 `[DEV]` 监视器存在。
2. 将阶段时间和事件间隔改成上表建议值。
3. 在 RECON 等待侦察生成，点击“到达”，观察目击与撤离。
4. 确认软警告和正式战前 Intel 只在阈值满足后出现。
5. 等待 EXPANSION，验证基地和至少一次行星扩张。
6. 等待 FORTIFICATION，验证黑洞要塞和巡逻事件。
7. 等待 WAR，确认第四窥视资产移交、正式战区 Intel、Omega/Human 错峰回合。
8. 对一个 `PLANNED` 事件点击“到达”，验证实体化；离开后验证卸载；再等待结算。
9. 关闭 DevMode：确认监视器与 `[DEV预览]` Intel 消失；正式解锁的 Intel 保留，未正式解锁的 Intel 不应残留。

## 5. 注意事项

- “到达”是有状态的测试操作，会改变玩家所在 Location，并可能立刻触发物化、接触、警告或战斗；使用前建议另存测试档。
- Dev 监视器只记录 **DevMode 开启期间** 的即时触发；战略事件列表本身来自存档状态，所以能显示开启 DevMode 前已经排队的事件。
- 普通模式不会发送 `[DEV危机]` 消息、不会创建 Dev 监视器，也不会提前补建任何危机 Intel。
- `src/data/missions` 未参与本功能改动，仍保持原位置和打包方式。

## 6. 占领区、殖民地互动与临时战线投影

### 原版地图隐藏

- DevMode 关闭时，精神创伤 faction 的市场以及带有 `$PTSD_controlled_territory` 的市场会设置为 hidden，不参与原版大地图殖民地标注。
- DevMode 开启时会临时取消 hidden，方便开发定位；关闭 DevMode 后观察器会自动恢复隐藏。
- 占领区不会从危机战略状态中删除。正式战区 Intel 仍通过控制色、战线和箭头提供大致位置推断。
- Dev 监视器的“精神创伤占领区”章节会列出每个市场的实际隐藏状态、双方注意力、累计轰炸损伤、防御舰队胜利次数，并提供“前往/到达”。

### 殖民地互动触发表

| 选项 | 触发条件 | 实际效果 | Dev 记录 |
| --- | --- | --- | --- |
| 远距轰炸 | 拥有 `25 + 市场规模 × 5` 燃料 | 有限降低 Omega 控制；增加精神创伤注意力和少量人类关注 | `HARASSMENT_BOMBARDMENT` |
| 尝试试探 | 无额外资源条件 | 生成占领区防御单元，主动攻击玩家；三天后返航并消失 | `PROBE`、`DEFENSE_SPAWNED` |
| 尝试交涉 | 无额外资源条件 | 播放恶意信道攻击剧情；剧情结束生成较小响应舰队 | `NEGOTIATION`、`DEFENSE_SPAWNED` |
| 全面轰炸 | 玩家击败该殖民地的防御舰队，且拥有 `110 + 市场规模 × 16` 燃料 | 显著增加精神创伤注意力；提高人类关注；降低控制和改造等级；排队新的卫戍事件 | `DEFENSE_DEFEATED`、`SATURATION_BOMBARDMENT` |

防御胜利通过实际战斗监听器判定，不会因为舰队正常返航或超时消失而误判。全面轰炸后会消耗这次“防御已击溃”状态，需要再次击败新的防御反应才能再次进行。

所有互动结果保存在 `PTSDCrisisState.OccupationData`：轰炸次数、试探次数、交涉次数、防御胜利、双方注意力、累计损伤和最后互动类型都可供后续剧情使用。

外部剧情和特殊战役可通过 `PTSDOccupationAPI.registerExtension()` 注册 `InteractionExtension`，追加选项、处理选择并接收所有占领区行动回调。

### 战线性能与投影验证

- 战略层仍以本地权重和伪随机结算为事实来源，实体舰队不是战果来源。
- 普通战线投影同时最多存在 5 支，单个星系最多 2 支。
- 每次投影最多持续约 2.5 游戏日；离开物化范围或期限结束后会卸载，强度写回战略事件。
- 同一事件卸载后至少 5 游戏日才允许重新投影；一次实体化后设置 7 游戏日重复冷却。
- 玩家进入近期发生过远程结算的星系时，可以生成一处持续约 5 天的战斗残骸。每个星系至少间隔 4 天才投影下一处残骸。
- Dev 记录名称分别为“战略事件实体化”“战略事件卸载”和“战线残骸投影”，用于确认实体生命周期。
## 7. 战区态势地图、右键安全与时间轴迁移

### 分屏地图观察

1. 在 DevMode 监视器中点击 **查看战区态势情报**。
2. 界面左侧应为占据主要空间的自绘全星域图，右侧为可独立滚动的战线详情、玩家标记与殖民地舰队控制台；地图本身不再随右侧内容滚动。
3. 在左图使用鼠标滚轮缩放（1×—8×），按住左键拖动视野；缩放以光标附近为中心。
4. 将光标移到星系节点、宽推进箭头或粗战线边缘：左图底部应显示当地攻击权重、人类防御权重、控制率、实体化状态和事件说明。
5. 精神创伤控制区以紫色半透明晕染表示；人类侧、玩家标记和外部模组通过 `PTSDCrisisAPI` 注入的舰队贡献使用各自颜色。活动战略事件直接覆盖为带箭头的线，不再另放一张原版地图。

### 右键崩溃回归测试

1. 在左图空白处和星系节点上反复点击右键。
2. 预期结果是视野恢复为全星域，不应出现原版“放置自定义图标”菜单，也不应打开任何子对话。
3. 关闭 Intel 后继续航行，确认没有 `getCoreUI() is null` / `getDialogParentForSubDialog()` 异常。
4. 按住左键连续拖动地图并同时经过星系节点和战线；不应出现 Attempt to access data of a consumed InputEvent。悬停说明应在拖动期间正常更新。

原因说明：Intel 内嵌的原版 `createSectorMap()` 会暴露只适用于完整 Core UI 的右键标记入口；当前实现已完全移除此组件。自绘面板会消费自身范围内的滚轮、拖拽及右键事件，右键仅执行安全的视野重置。

### 时间轴观察

- 新开局和旧存档的监视器都不应再显示约 `-644000` 的日期；阶段显示“已持续 N 天”，所有下一事件显示“N 天后”或“已到期”。
- 第一次以新版代码载入旧存档时，Dev 即时记录会出现 **状态迁移**：所有旧负数绝对日期统一增加固定纪元偏移，事件之间的剩余时间不变。
- 可记录载入前后的任意 `resolveDay - 当前日` 或下一侦察倒计时；迁移前后差值应保持一致，不应造成旧事件集中立即结算。
- 关闭 DevMode 后，迁移仍作为存档兼容修复保留，但迁移通知、Dev 预览与内部倒计时不会暴露给正常玩家。
## 8. 第四窥视 / 精神创伤 AI 核心军官与奖励

1. 开启 DevMode 后载入旧存档；模组会扫描当前所有 Location，并只修复第四窥视、精神创伤舰队中仍为默认军官的舰船。既有非默认剧情军官不会被覆盖。
2. 接近任意侦察、入侵、卫戍、要塞巡逻或旧星区预置舰队。交互页中舰队司令应显示“第四窥视观测单元-####”或“精神创伤子人格-####”，各非战机舰船也应拥有 `PTSD_core` AI 核心军官及对应技能。
3. DevMode 新生成舰队无需重新载档，应在 `FleetFactoryV3` 创建阶段自然获得同类核心军官；精神创伤种子巡逻不再关闭 `withOfficers`。
4. 击毁或击瘫由 `PTSD_core` 指挥的舰船并赢得战斗。战利品中每艘普通战损舰船应加入 1 个“创伤协议残片”，空间站加入 3 个；左下角同时显示 `[DEV核心奖励]` 数量记录。
5. 战利品中不应出现 `PTSD_core` 商品本身。该商品继续保留 `no_drop`，军官的 `aiCoreId` 仅用于游戏识别 AI 军官。

### 精神创伤舰队自动分公式

`最终 FP = 基础 FP × 未知事件强度倍率 × (1 + 严重度 × 0.65) + 动态 Flat + 设置 Flat`

- Luna 设置 ID：`PTSD_unknown_event_strength_multiplier`，范围 `0.5–10.0`；额外 Flat 为 `PTSD_unknown_event_strength_flat`，范围 `0–200`。
- 动态 Flat 上限为 `+200`，设置 Flat 可再增加 `0–200`。阶段基础值依次约为：侦察 `+15`、扩张 `+45`、要塞化 `+85`、全面战争 `+125`。
- 近期远距轰炸、全面轰炸、试探、交涉、防御战和异常接触会继续提高 Flat；占领区行动影响会在约 120 游戏日内逐渐衰减。
- 事件严重度由事件类型和战略强度决定；进攻、卫戍、黑洞要塞巡逻具有额外严重度，终局事件可超过普通 `1.0`。
- 已接入占领区反制、据点巡逻、种子巡逻、远征储备军和战区事件实体化舰队。后续生成器应统一调用 `PTSDOmegaFleetScaling.scale()`，并用 `record()` 写入 Dev 数据。
- Dev 监视器顶部显示当前倍率与动态 Flat。每支新舰队还会生成“精神创伤舰队强度”记录，显示基础 FP、倍率、Flat、严重度和最终 FP；舰队内存同时保存 `$PTSD_base_fleet_fp`、`$PTSD_scaled_fleet_fp`、`$PTSD_dynamic_flat_fp` 和 `$PTSD_event_severity`。
- 平衡换算可按“每约 50 FP 支持增加一艘驱逐舰或两艘护卫舰”观察，但最终舰型仍由原版 `FleetFactoryV3`、势力舰船池和舰队类型共同决定。

## 15. JAR 热更新与新闻 CSV 编码

1. `data/config/PTSD_crisis_news.csv` 必须保存为 **UTF-8 无 BOM**。文件首字节应为 `69 64 2C`（`id,`），不能是 `EF BB BF`；否则 `getMergedSpreadsheetDataForMod("id", ...)` 会把首列识别成 `\uFEFFid` 并报告 `JSONObject["id"] not found`。
2. IntelliJ Artifact `Omega Psychasthenia:jar` 继续启用 `build-on-make`，保留随编译打包工作流。若打包发生在游戏运行期间，测试前必须完整重启 Starsector，使类加载器重新读取 JAR 索引。
3. 游戏的 `URLClassLoader` 会缓存 ZIP 条目偏移；运行中随编译打包后，当前游戏进程可能在后续延迟加载内部类时出现 `ZipFile invalid LOC header`，外层通常表现为误导性的 `NoClassDefFoundError`。这不限制自动打包，但该次测试需要重启游戏。
4. 若已经在游戏运行期间改写过 JAR，即使磁盘上的新 JAR 能通过完整性检查，也必须完全退出并重新启动游戏；旧进程缓存的 ZIP 索引无法由模组代码修复。

## 16. 本地恐慌与 Je Otloes 事件

### 本地恐慌观察

1. DevMode 下打开 **[DEV] 精神创伤危机监视器**。顶部的“全局恐慌加成”在当前内容中应始终默认为 `0`；新闻发生后也不得变化。
2. 查看新增的 **殖民地局部恐慌（侦察信息表）**。每行显示实际恐慌、新闻/事件累积、邻近压迫、全局加成和最后来源。此表直接读取 `SystemData.colonyPanic`，与侦察和攻击权重共用星系战略记录。
3. 强制抽取带正恐慌的新闻。新闻仍生成明确目标星系/实体；目标周围殖民地按距离获得不同增量，远于约 `18000` 超空间坐标距离的殖民地不受该新闻影响。
4. 将阶段切至扩张、要塞或战争，并靠近母星/精神创伤控制区观察。邻近压迫应随阶段增强、随距离平方衰减；同样新闻增量下，前线殖民地的实际恐慌高于远方殖民地。
5. 本地恐慌升高后检查市场：流通度最多降低 `65%`；同星系所有市场的战斗舰队规模倍率都会按该星系最高恐慌降低，最低至 `25%`，不要求舰队来源就是最高恐慌的那颗行星。
6. 将某星系恐慌提升到 `30+` 并推进 6–13 日检查周期。可能出现“趁乱活动的海盗”；全宇宙同时最多 4 支，完成短期袭扰后撤离并消失。

3. 调查结束时 Je Intel 进入“重要”状态，给出离玩家最近的非敌对殖民地并提供前往按钮。抵达该市场时会面直接接管交互。

## 18. Dev 变量与事件控制台（2026-08-20）

## 19. 战略舰队投影与战场遗迹

- 玩家进入战略事件的渲染范围后，非追杀事件按总强度拆成 1–3 支临时分遣舰队；它们会在星系中的主目标、跳跃点或非恒星行星之间选择相同或不同目标。

- 战略结算的投影窗口、残骸区、普通舰体残骸和不可回收精神创伤残舰均延长至 60 日。

### Dev 控制台
