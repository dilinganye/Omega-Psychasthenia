## 接口与存档

CSV 的 `target` 为各卡独立 `CUSTOM(...)` 处理器，`delivery=SCRIPTED`。可选 `visibility` 为 `PUBLIC`、`INTEL`、`DEV_ONLY`、`NONE`，旧行默认 `PUBLIC`。处理器实现 `ChainNewsHandler` 生命周期：条件、开场、推进、选择。统一导演只调度并去重，不依据按钮文字猜任务类型。`N-CUSTOM-01` 继续使用普通 `CustomNewsHandler`。

`PTSDLateState.FTChain` 保存版本 2、节点、实体 ID、时限、定金和尾款标志、实际预留资产、残片授予及一次性结局。旧存档已投放的 FT 保留原结算并归档；旧未完成卡不重演，也不从旧新闻虚构运输损失或玩家证据。开发者面板应将新旧事件来源分开标记。

FT-10 的六次击毁从安装本版后具有真实战斗回调及舰队 ID 的记录开始统计；旧版总交战数不自动换算成击毁。FT-09 的 DEV 运输移除会明确标为模拟来源，正常战役只接受实际运输舰战损。

## 验收重点

实测每条线的触发与失效，尤其确认：FT-02 新闻不会标出正确黑洞；FT-03 没有旧三次绕行门槛；FT-05 的四次报价不扣钱；FT-08 必须依赖私改许可；FT-09 仅从真实运输损失启动且残片只给一次；FT-10 不把估计准备点写入真实账本。读档与重复战斗回调不得重复结算。
