# 侦察报告与条件新闻运行契约

本文记录本轮实现。阶段时长仍由现有危机阶段设置控制；本轮没有引入新的阶段门槛。侦察阶段结束时未覆盖的星系保留盲点，营建与要塞化继续用较低频率派出侦察舰。

## 侦察报告

- 每艘侦察舰抵达任务区时报告一次，以后每 `PTSD_recon_report_interval` 日报告一次；每天测得的本地舰队强度最大值另行记录。每次报告必含当前任务星系。附报分支依次为玩家近期已上传踪迹 20%、最近三星系 25%、最近双星系 40%、仅本地 15%。附近星系不含当前星系。玩家踪迹无有效来源时回退本地。
- 报告先存于 `PTSDCrisisState.pendingReconReports`，1–3 日后由仍存活的来源舰队上传。成功撤离的舰队在退场时提交其余资料；被击毁或异常消失的舰队丢失尚未上传的报告。批量报告和每日最大值均保留来源舰队、目标、来源组、采样日及到期日。
- 远距估测只给出带误差的殖民地存在信号与粗档舰队强度，不给出市场防御精值。已上传的远距“无人且低活动”报告在有效期内暂缓实地访问；过期或新线索出现后再入候选。实地确认无活跃殖民地后 2–4 日内转往最近的未实测星系，单任务最多转向三次。不能从公开新闻或玩家单方面目击制造敌方证据。
- 新存档字段版本为 14。旧存档从空的待上传队列开始；历史上有来源且可验证的证据保留。DEV 面板显示实地覆盖、仅远距覆盖、低活动暂缓数、待上传队列及最近改道原因。

## CSV 接口

`data/config/ptsdCSV/PTSD_crisis_news.csv` 的原有列保持兼容，新增可选列：

| 列 | 用途 |
| --- | --- |
| `delivery` | 空值/`AMBIENT` 为原随机新闻；`SCRIPTED` 由后期事件导演按阶段投放；`CONDITIONAL` 由世界目标与条件导演投放。 |
| `trigger` | 条件事件的真实目标类型：`SCOUT`、`REPORT`、`PLAYER_TRAIL`、`RELAY`、`JUMP`、`MARKET`、`WILDERNESS`、`BASE`、`OUTPOST`、`TRANSPORT`、`FORTRESS`、`FORT_SMALL`、`FORT_STABLE`、`FORT_MEDIUM`、`FORT_EDEN`、`FORT_BLOCKED`、`FORT_MOVING`。 |
| `action` | 玩家到场核实后的行动文字；由新闻 Intel 展示。 |
| `remoteOutcome` | 玩家未在限期内处理时的可见结局文字；实际设施、运输及舰队依原有战略模拟继续。 |
| `omegaResponse` | 现场干预后、敌方预算允许时的应对文字。工程类回应会预留 10 准备点和 30 战略资产生成实际驻防事件；其他回应花费 3 战略资产并提前下一次侦察。 |
| `effect` | 现场行动的结算类型：`VERIFY`、`JAM_UPLOAD`、`DELAY_SCOUT`、`SHARE_INTEL`、`COORDINATE`、`DEFEND`、`MISDIRECT`、`DISRUPT_OUTPOST`、`DELAY_FORTRESS`、`DELAY_TRANSPORT`、`EVACUATE`。 |
| `choice1` / `choice2` | `SCRIPTED` 后期事件的两项选择；两项都为空即短卡。 |
| `minDay` / `priority` | 相对阶段开始日的最早投放日，以及条件新闻抽取权重；后期旧卡沿用原日程。 |

`R2-01` 至 `R2-15`、`E2-01` 至 `E2-15`、`F2-01` 至 `F2-15` 是 45 组新条件事件。`FT`、`MB`、`WR` 共 36 组后期事件的新闻文字也由该 CSV 提供。每张条件卡每档最多自然投放一次，使用实际世界目标；目标消失、调查超时与误报均有独立结局。普通新闻不会因自身发表而增加敌方侦察置信度或目标权重。

## LunaLib 与测试

新增设置只在 DevMode 出现。四个报告概率采用顺序截断，合计不会超过 100%；上传和无人改道的最大值至少等于最小值。侦察、营建、要塞误报率依次不升高。修改设置只影响之后的结算，已上传证据和已投放事件不回算。关闭 DevMode 后精细参数恢复内置默认值。

DEV 控制台列出当前阶段可用的 CSV 条件事件与后期事件，未满足条件的事件显示具体缺口；强制触发会再次复核目标。普通玩家只有与自身资产或限时行动相关的条件新闻收到提示，其余留在新闻 Intel。测试时需分别检查侦察舰在上传前被击毁、自然撤离、远距误判、无人改道、工程各等级目标消失与旧存档载入；编译通过不代表已在游戏战役中验证。
