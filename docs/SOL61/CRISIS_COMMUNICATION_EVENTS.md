# 危机通讯随机事件方案

状态：设计待讨论，尚未接入游戏。

最新确认：沉默与异常回应较常见，资源与伏击较少见。WAR阶段开始后不接通玩家消息，不再产生新的通讯抽签。已生成的地点任务不因无法接通而自动消失。2026-10-19 用户确认：完全随机，不要求玩家进一步解析才可能受影响。

## 共同规则
接通时抽取并持久保存本次接触结果。重新打开、存读档不重新抽签；离开对话不会凭空取消已发生的电子战或已生成的地点。随机不等于泄露敌方部署：只能显示通讯内容及现场观察。事件文本集中外置，采用明确处理器；沿用已有地点模板、任务生命周期与高能/普通调查归类。哪些分支可用于哪些危机身份仍待确认，默认不能让情节互相矛盾。

| 随机结果 | 玩家可见过程 | 实际机制建议 |
|---|---|---|
| 无声接通 | 信道占用持续上升，却没有任何回答；结束时收到自己刚才的呼叫 | 纯氛围，也可独立抽中短时传感器干扰，不能用沉默判断安全 |
| 识别污染 | 舰船识别码被换成一串港务编号 | 临时降低传感器效率，持续时间与上限明确；不永久改舰名 |
| 逆向握手 | 接收指示变为上传指示，通讯官无法确定哪些数据被读取 | 临时暴露信号；响应队前往最后已知位置搜索，不全知跟踪 |
| 指令回灌 | 收到由本舰签名、时间戳尚未到来的推进命令 | 一次短暂阻断脉冲；避免循环锁死操作，强度待定 |
| 空仓交付 | 对方只发送坐标及“已交付”，随后切断 | 真实藏匿点，包含物资或损坏记录；使用资源预算/一次性领取 |
| 无人接收 | 一处有人使用过的存储设施仍在向不存在的船只发放物资 | 可回收有限资源，调查记录提供后续地点；不保证有敌舰 |
| 过期坐标 | 地点真实，货物已被取走，留有可追踪残迹 | 空藏匿点或正在离开的运输队，玩家可选择追踪 |
| 诱导交付 | 相同交付格式与真实资源分支一致 | 坐标处伏击；可能先有少量真实资源，不能仅凭文案辨真假 |
| 残响求救 | 求救者反复使用玩家一名船员的名字，但记录中没有此人 | 残骸、真实幸存者、无人广播三种现场差分 |
| 路径校正 | 发来的航段与现有导航略有偏差 | 指向安全航段、异常观测区或诱导路径；不强制改玩家航线 |
| 第三方插话 | 另一段通信短暂覆盖主信道，像是在纠正刚才的坐标 | 两个证据点可交叉核验；可能有人类遗留资源，不直接揭示敌方动机 |
| 镜像点名 | 依次叫出舰队内若干实际舰船的识别码，最后叫出一艘不存在的船 | 可纯叙事，也可产生短时幽灵信号；不真的删除或复制玩家舰船 |
| 不合时宜的停火 | 对方要求玩家等待“另一批接收者” | 可能短暂停留、另一支事件舰队抵达或无事发生；不得擅自改变全势力外交 |
| 断续广播 | 公共广播中出现与当前地点相符的天气或港务信息，却来自无人星系 | 引向废弃设施、旧档案或纯粹无结果的通讯；保留谜团 |

## 待确认的实施参数
- 已确认不等概率；建议初始分组权重：沉默35%、异常回应45%、资源线索10%、伏击线索10%，具体数值待调试。
- 电子战持续时长、冷却、是否影响CR；建议主要使用传感器/信号/推进干扰，不直接毁船。
- 同一舰队一次任务最多产生一个有实际收益或追兵的通讯事件，防止反复呼叫刷资源/舰队。
- 同时存在的通讯地点数量与有效期；需要可放弃、清理和DEV单独触发。
- 是否让第四窥视与精神创伤共享全部分支，或保持可观察但不绝对的风格差异。

## 风暴侦察修复（源码完成）
生成半径1200–1800改为600–900；生成时传感器扫描清冷却后启动一次。原地停留2个未暂停推进秒后才执行逃离。风暴专属失联卸载必须先被玩家目击，再连续不可见0.2游戏日；普通现场侦察队沿用原规则。30日生命周期兜底保留。
测试：DEV风暴侦察测试，观察扫描、两秒停留、常速撤离、追踪后加力、失联退场；暂停不计停留时间。极低传感器或风暴遮蔽时不得刚生成就失联卸载。需要实机检查时长与可见性。
