## 旧存档崩溃的原因

已核对 `starsector-core/starsector.log`：`PTSDCrisisIntel.abandon` 调用 `PTSDInvestigationRewards.hasEvidence` 时，访问空的 `i.scene.portEvidence` 并崩溃。

这次是现场状态新增字段缺少加载补齐和空值防护，**不是新闻 CSV 删列造成的解析异常**。旧存档没有该字段，反序列化后未必执行 Java 字段初始化器；先前只修了最外层状态，没有补齐嵌套的现场集合。

现在每次读档的一次性状态修补会初始化现场 nodes、owned、fleets、visited、portEvidence、pulsed 等缺失集合，以及调查的实体/回收列表。只补空集合，不重置已有证据、差分、倒计时和奖励。证据判断本身也允许 null，以防回调先于修补抵达。

无需为此手工编辑或删除存档。新 CSV 和上轮 eventLoc 接口的 JAR 仍须配套，不能只替换 CSV 后继续使用更早的加载 JAR。

## 快速验收

1. 退出游戏，备份模组与存档，将本批 `package` 内文件合并到模组目录后重启。只复制 package，不复制 classes/tests/dlc-example。
2. 载入本次崩溃之前的旧存档，找到原来的调查，点击“放弃调查”。应正常移出列表；没有证据的调查不补发报告，有部分证据时只结算一次。另存并重载，不能再次出现或重复给奖励。
3. 用已有 DEV 的现场测试入口生成一条普通调查和一条 Je 调查，接取并完成现场。获得报告后分别打开失联信息，两个分支、顶部当前任务和地图按钮均不能继续指向已结算条目。
4. 接取至少三条不同时间、不同星系的调查。逐个点击四种排序，确认同一分支内顺序变化；切换其他 Intel 再回来、存读档后，所选排序应保留。移动玩家位置后重开面板，距离顺序应按新位置计算。
5. 选择只有基础取证完成、仍可下达行动的条件调查：在其行动期限内必须保留。执行完取得奖励后移出；不执行直到过期也移出。
6. 留一条普通调查和一条 Je 调查至期限届满；不必等待新新闻刷新，重新打开列表应已清理。检查追兵仍按自身行为运行，取消列表不能让敌舰凭空消失。
