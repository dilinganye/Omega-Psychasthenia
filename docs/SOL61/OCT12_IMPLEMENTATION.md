## 已修复的具体路径

### 出兵与要塞

- WAR原来没有runRecon补充入口，证据过期后pickAttackTarget又必须要求有效证据，可能长期没有合格目标。战争现在继续使用原后期侦察周期与盲区条件，不授予敌方全知地图。
- 攻击预算原来必须付得起整份期望兵力才行动。现在按实际战略资产及准备点可支付上限缩小规模，最低55FP；仍不足就等待生产。战争优先安排进攻，再处理驻防与扩张，不免费补资源。
- 兼容整理原来可能清空无战略事件ID的本模组运输/任务舰队命令，再永久改为守卫。现在跳过已标记危机任务舰队，真正旧版无分类舰只整理一次，保护运输入站流程。
- 首座要塞未开工时，不再用重复母星驻军消耗其前置准备金。允许WAR继续未完成的要塞建设，保持资源和总数上限；开工失败两日后再试，成功才等待30日。
- 选址识别多星系统中的黑洞伴星，而不只主星；施工轨道和黑洞坍缩操作都使用该黑洞对象。新造要塞与护卫设置正常CR；升级保留旧CR上限，不借升级恢复损伤。
- 旧要塞接管由每个心跳全区搜索改为一次性登记，已有/已毁记录不覆盖。星系解析兼容原版optionalUniqueId与持久getId不一致的情况。

### 新闻与调查

普通可调查新闻真实分支25%→44%。非沉寂阶段原5%跟踪器支线仍保留，假线索为51%；沉寂阶段没有跟踪器，假线索56%。只对之后首次记录的线索抽签，已保存的结果不重抽。

记录成功后明确显示失联调查Intel，即使新闻列表当前存在筛选；聚焦最新接取任务，在顶部放置“导航至当前调查地点”，地图定位也优先该任务。失败接取留在原条目。战争警告不再反复结束失联Intel；旧档已结束的调查Intel在再次需要时重新创建，任务记录保存在原状态中。

侦察有效长度为现有collect_data_time×2（默认365→730日；若已有Luna300则为600日），火力侦察时间门槛同比调整。要塞突袭最早10→20日、正常动员最早30→60日、最迟期限默认180→360日；仍受准备点和情报条件影响，不承诺固定停留360日。设置说明注明实际×2，已有存档阶段开始日和历史不重置。

### 自绘与联盟

PTSDCommandSurface直接绘制底板、细网格、定位角和模块强调线，不引用原版内部UI实现或背景纹理；保留公开字体与输入API。新闻、失联调查、FT调查、Je任务与后期事件簿使用可滚动档案阅读面板，原文和任务选项继续由既有显示逻辑提供。战线使用自绘地图与作战侧栏；联盟自绘四个可点击导航页签、四张统计模块、地图及表决/资源分支。DEV只修复运行问题及数值说明。

联盟席位按既有规模与贡献各50%，90日前贡献以一半计入席位（累计贡献饼图仍显示原累计值，90日图只含近期）。无已记贡献时贡献半区沿用规模比例，避免凭空给未知功绩。成员范围及行动发生时的贡献归属保持。

提案提交时锁定席位与逐势力票。NPC按受威胁情况、外交关系、可核实人类报告和提交的支持方式答复；玩家独立成员有赞成/反对/弃权入口，未答复不自动赞成。票数须超过全部锁定席位的一半；旧未决议案第一次载入新规则时重新给予2日答复窗，不补造历史投票。

通过后从预留额度派出实际后备队，途中不增加防御；抵达后加入战区，重复推进不重复加兵力，战损/撤走扣回对应贡献。调令对应地图势力色虚线，抵达贡献只记录一次。近玩家时可在超空间或目标星系实体化，进入目标星系后执行防守命令；舰队规模不能超过拨款。地图右键新增以60补给或30日殖民地出口支持协防提案。既有邀请入盟、2日答复、关系下限与四张饼图沿用并接入新导航。

本轮没有完成此前所有政治深度条目：动态否决资格、宿敌争端/退出调解、秘密贿赂等仍在目标表中，不能因新增表决界面而自动勾选。

## 性能定位证据

1. 现有starsector.log最后写入时间为2026-10-05，包含PTSDLunaConfigVisibility.removeSettings反射被沙箱拒绝的重复异常。它是已有运行证据，不是本轮新源码的性能实测。现改为直接调用已安装LunaLib的公开getSettingsData/getModID/getFieldID，失败也不再每帧重试。
2. PTSDCrisisDevWatcher原约0.2实秒调用syncMapVisibility，后者全区搜市场/舰队并重复清理市场内容。现只在首次观察/DevMode切换调用；日常兼容仍由危机主循环处理，已隔离市场不重复拆产业/清货物。
3. initializeOrMigrate原每帧解析隐藏母星市场；已移入心跳。resolveMarket缓存仍附着于原实体的有效市场，实体脱离或换市场立即失效；离线测试1000次读取仅一次全区枚举。
4. findEventFleets原每个事件每个心跳再扫描全区舰队；现在每次加载建立一次旧事件ID归属，之后用持久ID列表。
5. showHardWarning原每个战争心跳再次transferWatcherToPsychasthenia，绕过上轮的阶段同步降频。现只首次战争警告执行，普通运行保持分批兼容普查。

这些是代码路径上的修复，不代表已测得FPS提升。场景对照仍按PERFORMANCE_TEST_PROTOCOL进行。
