# 2026-10-18 巡回侦察与指定首波名单

状态：源码实现；临时 Java 8 目标编译、14 项离线回归通过；游戏内验收待进行。没有覆盖加载 JAR。

## 已确认需求

- 普通巡回侦察从 FORTIFICATION 开始，涵盖 MOBILIZATION，到 WAR 停止新增，每 5 游戏日一队。
- 随机有人星系优先核心星域；实际前往另一个有人星系，完成后返回最近的精神创伤控制星球，返抵才上传到访资料并卸载。
- 名单列最终为 `starID,reasonID,requireModId`。`starID` 填恒星实体 ID，不是星系名、星系 ID 或殖民地 ID；双星/三星中的恒星同样解析到所属星系。
- 目标仅限该星系内部全部非精神创伤殖民地及舰队，不扩大到该势力的外部殖民地。使用作战，玩家可截击进攻队。
- 默认开启、逐条关闭；原因直接显示，不作为本地化键解析。显示需求模组及来源模组。
- 名单 RECON 武装侦察默认每 30 日；要塞及动员期骚扰默认每 15 日，均可在 LunaLib 调整。

## 配置接口

配置路径：`data/config/ptsdCSV/PTSD_first_wave_targets.csv`。
任何启用的模组均可在自己的目录提供同路径文件。按贡献模组单独读取，来源由加载器取得，不能由 CSV 冒充。主模组提供空表头，不预置破坏性目标。

```csv
starID,reasonID,requireModId
example_star,该星系的研究设施曾主动回应异常信号,example_mod
```

上例为占位说明，不能原样作为有效目标。需要替换成目标游戏世界中真实恒星 ID；需求模组为空表示无额外依赖。逗号和换行依照 CSV 引号规则处理。列名保持大小写。

- LunaLib → 本模组 → **指定打击名单**：总开关、两个周期参数、各条目开关和详细资料。
- 同一模组重复恒星 ID 明确报配置错误；不同模组可各自贡献同一恒星，保留独立开关。只要还有一条有效且开启的贡献，该星系就启用，但不会重复派同一期兵。
- 开关键由来源模组 ID 与恒星 ID 生成，改行顺序、原因或模组显示名不会重置玩家选择。
- 未满足 `requireModId` 不派兵。找不到恒星或误填普通行星时记录原因并等待合法目标，不替换成别处。
- 关闭只阻止后续新任务；已经出发的队伍继续执行，仍可被玩家消灭。已经结算的首波不会因开关反复切换重新刷出。
- 修改 CSV 后重新启动游戏；游戏内周期/开关在下一次调度读取，不需要重新编译代码。

## 运行机制

### 普通巡回侦察

核心星域候选权重为其他有人星系的 3 倍，不排除外围星系。先在第一星系的跃迁点附近安全位置出现，前往真实殖民地附近采样，再跨星系前往另一有人星系。只有一个合法有人星系时，在该处采样后返航。

每处采样驻留 1 日；数据在采样时固定，保存在舰队脚本中，不进入普通定时上传队列，不附赠未到访的周边星系报告。两个航点完成后寻找最近的本模组控制星球；控制权改变时每 5 日重新检查。距离星球 700 范围内返抵后一次上传，并按既有事件舰队存活 FP 的一半回收战略资产。途中失去舰队则资料遗失。

120 日仍未完成调查则中止剩余航点，携已有样本返航。若已无控制星球，保留载体等待新的合法返航目的地，不假装上传。已出航任务允许跨入 WAR 后完成，不会因阶段变化凭空消失。

### 名单武装侦察、骚扰

直接进入名单星系，仍有真实舰队、前往现场、停留及返航过程。普通阶段舰体与数量上限继续生效，RECON 不会跳过单护卫起步成长规则。武装采样取得该星系部署快照，完成上传后纠正原有粗略战争估计；被截击可丢失该队载有的情报。

骚扰驻留 5 日并执行武装现场行动，不在战前直接消灭殖民地。新一期产生后不把正在航行的上一队瞬间移回目标。定期任务及报告均保留实际时间，不在读档后补发多期。

### 名单首波

每个目标殖民地一项免费攻势，另有一项覆盖该星系舰队的清剿行动；无殖民地的名单星系也有清剿。目标在该次出兵时冻结，部署记录持久保存。名单部队不消耗战略资产/战争点，也不返还免费首波资产；普通外围首波仍遵守既有半价出兵、存活 FP 的 75％返还。

所有任务复用虚拟行军、到达告警、附近实体化、真实战损与返航流程。实体化之后不会重新变回虚拟。玩家击毁某一项攻势不会被同一名单任务免费补出。名单仅绕过常规选址免疫/权重，不绕过行军与胜负结算。

舰队清剿分两条路径：

- 实体清剿队搜索真实节点，仅截击自身侦测到的本地目标，近距实际接敌；玩家介入和战损影响结果。不会用虚拟扣分删除其面对的舰队。
- 玩家不在目标星系且清剿队尚未实体化时，每日最多结算一支本地舰队的模拟交战，消耗双方兵力；积累伤害按实际舰船 FP 扣除舰船。已经离开星系或正在其他战斗中的舰队不强行结算，玩家主舰队永远不作为离屏扣除对象。
- 清剿最多持续至理论抵达后 30 日，未清除目标记为未完成，幸存者返航；不保证无视玩家和增援强行获胜。该上限属于本轮实现的节奏值，待实机校准。

## 快速验收

1. 在测试副本 CSV 填入一个已知真实恒星 ID。重启游戏，LunaLib 检查默认开启、来源/原因/依赖可见；分别关闭条目、总开关，检查停止新增。
2. DEV危机控制台 → 后期控制区域 → **校验指定打击名单（只读）**：日志应显示启用状态、依赖和解析结果；错误 ID 不应产生替代目标。
3. 切到 RECON → **测试：立即执行一期侦察与名单行动**，立即生成名单武装队。第一阶段时间上限和数量成长仍有效。
4. 切到 FORTIFICATION，再点击上述按钮：立刻执行普通一期及名单骚扰，不必等待随机事件。在 MOBILIZATION 重复检查；WAR 不再提供该战前按钮。
5. 跟随普通队观察第一处采样、跨星系第二处采样、回到控制星球。通过开发情报记录核对：采样时没有定时上传，返港才有报告上传。用战斗消灭另一队，确认其样本没有上传。
6. 准备正常首波预算并进入 WAR，名单内所有非危机殖民地应各有免费作战记录及额外舰队清剿，外围普通目标仍收费。全星域范围不应被扩张成该势力的其他殖民地。
7. 在行军位置/目标星系拦截一支名单队并击毁，确认它的攻势失败且不重刷。同星系其他独立攻势仍可能存在，不能把“击毁一队”等同于击毁整个首波。
8. 玩家远离目标时检查每日模拟战损；到场后检查实体队实际作战，不能继续凭空删除防守舰队。完整返回的免费首波不增加资产。
9. 存读档后复查周期、载有样本、首波部署去重和 Luna 开关；检查多条跨模组指向相同星系只生成一套本期任务。
