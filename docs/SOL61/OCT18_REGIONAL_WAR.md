# 2026-10-18：节点巡逻、阶段扩张与区域战争

状态：本轮源码已实现；临时 Java 8 目标编译及离线回归通过；未覆盖加载 JAR，未完成实机验收。本文件替代旧文档中“最多四处首波爆发点”和“战争波次一开始就全部实体化”的描述，不表示此前新闻/UI总体任务已全部验收。

## 用户确认

- 星系巡逻沿真实星球、设施和跳跃点往返；占领球另有附近近卫。
- 要塞阶段新增 **4** 处邻近无人星系占领区，数量通过 LunaLib 调整。阶段扩张、基础守军和两座同时开工的黑洞要塞免费投入。
- 首波打击全星域最外围殖民地。部署扣除名义分数的 **50%**，返抵后方返还存活分数的 **75%**；完整返回可获得名义分数四分之一的净收益。
- 普通首波预算不足不得宣战；应修正战前生产，不能借无限免费部队掩盖不足。
- 特异点：观测防御超过外围殖民地中位数 **3倍**，且超过普通攻势规模。倍数通过 LunaLib 调整。特异点对抗部队免费、不返还资产。
- 每支实体进攻分遣队每次任务最多呼叫一轮两支援军，支付真实预算。

## 已实现的源码行为

### 巡逻与占领区

- `PTSDControlledPatrolDirector` 不再从地形和随机偏移坐标抽取巡逻目标。巡逻到达一个真实节点后短暂停留，再前往下一节点；不按固定两三日强行改道。
- 节点包含非恒星行星、跃迁点、空间站、通讯中继、导航浮标和传感阵列。要塞护卫及通用精神创伤驻防/要塞巡逻也接入节点巡逻。
- 每颗占领球有独立、持久的近卫槽位，靠近占领球进行主动警戒。沿用原系统的按玩家所在星系实体化、离场保存存活分数和战损后30日补员；不是全星域常驻实体舰队。
- 要塞阶段按扩张前占领区计算距离，选最近的合法无人星系，每星系改造一颗行星。排除隐藏、隔绝、有人和没有行星的星系，缺乏合法地点时明确记录实际数量，不制造额外星系。
- 同批免费开工两座真实黑洞工程；正常第三座工程至少延后30日。缺乏两个合法黑洞时等待可用地点，不重复补发已执行的阶段投入。

### 首波与后续区域攻势

- 新增 `PTSDWarCampaignDirector`。以可攻击殖民地所在星系的空间凸包及3000单位边缘带识别外围，不依赖星域坐标原点；随着殖民地被占领，重新计算剩余人类殖民地的外层。
- 首波按观测防御分配兵力，当前名义兵力为观测防御的2.8倍（最低90）。强敌获得更多兵力，不靠固定四目标上限截断覆盖范围。
- 首波错开0至5日出发，模拟航程2至24日；未受玩家干预的计划在开战29日内抵达全部首波目标。抵达和占领是不同时间点，玩家救援与真实战斗可以推迟结算。
- 原来开战粗估使用“规模×8”、普通侦察使用“规模平方×9”的分数口径不一致，本轮统一。首次筹划开战时补齐既定的带误差情报，再审核预算，资源不足时保持战前阶段；不把情报写给玩家。
- 战前按全外围计划校准有效工业的生产能力：默认六个生产周期积累一轮基础需求，战时按三个周期补充；产出倍率仍生效，必须存在有效生产来源。准备点和战略资产存储容量随计划规模提高，避免旧200/5000上限卡死全域战争。非必要行星改造不能挤占战前首波预算。
- 首波之后以30日为基本间隔，攻势倍率提高可缩短间隔。选择外围较弱方向，并对该点12000单位范围内的全部可攻击殖民地安排行动；已有行动中的目标不重复派单。
- 一次区域行动按整区成本审核。资源受到损失而不足时每日重试完整区域，不只派出几个目标便谎称整区已覆盖。军工恢复、后续回收及剩余预算决定实际恢复时间；不能在没有资源和生产来源时无条件出兵。
- 特异点还需超过 `max(600, final_invasion_max_strength)` 的普通攻势规模门槛；三倍中位数只满足其中一个条件。

### 模拟、实体化与返航

- 战争事件保存出发、目标、离港和预计抵达时间。超空间按当前时间插值；玩家位于模拟位置4500单位内才投影，玩家在目标星系时也必须等到理论抵达时刻。
- 实体化后继续真实执行任务，不因玩家离开而卸载。大兵力拆为若干支舰队，当前每队基础上限600FP、24艘；保留真实成员生成，未生成的船不能当作实体战力。
- 模拟进攻使用实际当地防御进行结算，战略选址仍只使用敌方已有观测。未抵达友军不计入进攻加成；联盟抵达支援计入对应战区，实体后备队不重复计分。
- 模拟战斗有概率造成战损，剩余分数沿返航轨迹返回后才结算。返航途中被玩家靠近也会实体化。
- 实体部队返抵来源星系的设施、占领球或跃迁口才卸载和回收，不再因80日超时凭空消失。返航记录不会被历史事件裁剪提前删掉。
- 免费特异点部队回收为零，普通首波为存活FP×0.75，后续普通攻势为存活FP×0.5。原通用“成功任务额外奖励”不再给这些战争事件叠加。
- 玩家未被传感器发现时不触发专门反应。发现较弱玩家则迎击；发现较强玩家则紧急推进脱离、最多三次近距阻隔脉冲，并尝试支付一轮两队支援。
- 支援从来源星系实际出发，前往最后报告地点搜索，不按玩家实时位置全知追踪。失去玩家接触后主队恢复既定任务或返航。

### 新闻、战线与联盟

- 进入目标星系后发布红色遇袭通报；首波额外有港口告急及撤离报告，持久去重。
- 遇袭后才建立公开战区记录，接入既有联盟表决、增援和防线机制。新战区不执行旧式独立轰炸计时，避免重复打击。
- 玩家殖民地保留按首份可靠通报锁定的救援时间，不在玩家尚无机会抵达时直接按五日结算。
- 自绘地图只用已遇袭地点绘制大致攻势区域；首波按各受击星系分组，避免把整圈外围的凸包内部误涂成全部遇袭。
- 原版星域地图的 `ArrowData` 与战区侧栏原版“来袭方位”小地图均使用约略方向：真实来向加正负30度误差，箭头起点距目标2200至4400单位。误差写入事件，不随界面刷新重抽；不连接真实基地。
- 自绘海图保留低饱和半透明虚线。攻势轮廓在打开面板时生成，不在每次绘制时重新计算全体事件凸包。

## LunaLib 与 DEV

- 后期危机页：`PTSD_fortification_expansion_systems`，默认4，范围0至20。
- 后期危机页：`PTSD_war_singularity_multiplier`，默认3，范围2至20。
- 两项都属于普通模式设置，不依赖DevMode；新增占领区数量在阶段投入完成后不追补。
- DEV显示首波所需准备点、资产、实际外围目标数和区域攻势计数，移除旧“/4”提示。
- 要塞/动员阶段新增 **测试：补足当前首波预算（改变资源）**。这是明确的DEV资源修改，不属于正常生产，也不会自动宣战。
- 既有“立即推进一轮战区结算”可推进新战区事件；真实战斗及玩家救援保护仍有效。

## 验证与剩余实机验收

临时 Java 8 目标编译通过，未覆盖加载JAR。12项离线回归通过：

- 新增 `WarCampaignPolicyTest`：外围凸包、中心排除、平移星域、重复坐标、首波折扣、存活返还、特异点和往返插值。
- 新增 `ControlledPatrolRouteTest`：实际节点、地形排除、不创建随机巡逻Token、不打断途中任务、近卫只守占领球。
- 新增 `VirtualWarLifecycleTest`：到时抵达、通报去重、联盟战区接入、按时间接近、返航延迟、一次返还和历史保留。
- 既有9项：侦察编成、首次侦察现场、新闻现场机制、遭遇撤离、Luna格式、战争抵达、后期运行、任务规则、人类报告。

仍需游戏内核验：

1. 原版AI实际沿节点运动、近卫追击后回位、要塞护卫迁移后续巡逻。
2. 四处占领区和两座同批工程的实际落点、缺黑洞地图的等待说明。
3. 一个完整首波周期：所有外层目标、第一月抵达、强敌兵力、真实舰船组成及高胜率是否形成预期末日感。
4. 强弱玩家的实际传感器判定、紧急推进可用性、连续脉冲、两队援军行军、甩脱与恢复任务。
5. 存读档后的实体持久、返航实际路径、战损及单次回收；特异点无资源回收。
6. 自绘区域、原版箭头小地图、缩放、颜色和侧栏尺寸；当前离线测试不能验证OpenGL布局。
7. 同档航行帧时间，尤其是玩家接近大规模首波或特异点时的舰队生成开销。本轮不宣称已解决所有掉帧。

新功能没有专门补造旧档已错过的首波。旧档已保存的旧首波战区仍可按其原记录结束；后续新区域攻势使用本轮流程。正式验收首波应从尚未进入WAR的测试档开始。
