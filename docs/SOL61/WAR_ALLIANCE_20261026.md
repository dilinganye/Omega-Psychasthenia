## 2. 入口与参数位置

- 玩家联盟入口：Intel中的「人类联盟：指挥与战线」；页签为成员与入伙、议案与表决、调拨与补给、协同防线、行动与救援。
- 「行动与救援」包含地图、行动阶段条、定位、Je求援、战地回执和来源兵力账本。
- 「危机事件簿：待决命令」顶部也可进入联盟行动。Je联系人在出航/失联期间显示专项说明与入口。
- 战斗入口：WAR中与危机舰队交战，打开TAB；自绘紧急联络面板与原版指挥界面并存。
- 新参数集中在 `src/data/scripts/campaign/invasion/PTSDReliefSettings.java`：每个字段旁有中文名称。注册位置为 `src/data/scripts/PTSDLunaConfigVisibility.java`。
- 新参数均纳入LunaLib的DEV「自定义难度」、四个预设JSON和完整自定义快照；非DEV隐藏参数仍随难度切换。预设在 `data/config/ptsdCSV/PTSD_difficulty_presets.json`。
- Je字段：`PTSD_je_rescue_days=10`、`PTSD_je_escort_fp=80`、`PTSD_je_pursuit_fp=120`、`PTSD_je_missing_chance=30`。追兵与护航强度是初始测试值，不是已验证平衡值。
- 补员字段：`PTSD_relief_replenish_days=30`、`PTSD_relief_replenish_percent=15`。

## 3. 安装测试构建

1. 退出游戏，备份当前模组对应JAR、配置和测试存档。
2. 将 `build/sol61-war-alliance-20261026/package/` 下的 `jars/` 与 `data/` 合并到模组目录。该目录是可安装部分；不要复制classes或测试类。
3. 包内必须包含 `data/config/settings.json`，其中注册了战斗援军插件。只更换JAR而漏掉这一文件会没有TAB援军面板。
4. 此包叠加当前工作区既有新闻、曲线和现场源码。若你另行调整了配置或预设，先比较文件后合并。不要覆写自己的最新调参。
5. 启用DEV，用专门的测试存档测试。以下作弊按钮仅用于减少等待，不证明正常计时流程正确。

## 4. 最短验收路线

### A. 联盟入口与邀请（约一次短流程）

1. DEV将阶段转为WAR。通过DEV「打开联合总参部情报」或「打开战区态势情报」进入同一联盟界面。
2. 看成员与入伙页：霸主/速子仍有殖民地时应优先成为发起者；其他固定成员先有邀请回执，约2日后加入。
3. 玩家先拒绝再申请，确认拒绝不会偷偷入盟，也不会让左径变成成员。
4. 若测试档恰有创始势力灭亡，再检验英仙座联盟/教会接续。不要为测试在正式档删除殖民地。

### B. 战略援军与集结

1. 使用既有DEV进攻事件/首波测试，取得一个仍未结束且已有警报的战区。
2. 打开行动与救援，按「DEV：处理现有战区求援」。无合法来源时应显示原因；警报未满3日仍要等待。
3. 正常跑一次3日响应、5日整备。看援军真实生成在来源港口，整备期间不向目标防御加分。
4. 后续重复测试可按「DEV：跳过现有整备与集结等待」，仅缩短等待，不传送舰队或替代实际行军。
5. 跟随第一队到集结点。其他队未到时等候；第一队抵达满10日，已有队先行，迟到者到达后追赶。
6. 目标到达后再核对战区防御和实际舰船；反复打开Intel、保存读档不得再加一次防御。
7. 在目标失守的测试分支观察转驻：前往失守方向附近安全港，实际到达才开始30日驻防。若无安全港，等候合法返航路线。
8. 来源兵力账本中出征扣实际FP；有损失再返港只回补幸存FP。另让30日补员结算一次，不能复制在外兵力。

### C. 联盟战斗求援与左径必到

1. WAR中找一支真实危机舰队交战，不使用模拟器或普通人类内战。
2. 打开TAB查看紧急联络面板，点击求救。附近可用来源必定列入，远方可列入；没有兵力的来源不能凭空响应。
3. 保持未暂停计时：左径约30秒首轮，联盟附近约60秒，远方约120秒。左径后续90秒，联盟批次45秒。
4. 暂停一段时间，确认到达倒计时不偷跑。援军从战场边缘进场，不占用玩家部署点。
5. 延长战斗，确认左径按总FP额度停止，而不是无限刷舰；战损不重新补额度。
6. 如同一场战役发生多次交战，确认未重新抽额度。整场战役真正结束后才生成幸存者舰队、退回未进场的联盟预留。
7. 战后核对幸存者舰型和损伤。星系中的左径驻防10日再返港；超空间幸存者直接返港。只有实际到港才卸载，不能一出视野就消失。
8. 再与同一敌舰队发生一场新的独立战斗，应有新的战斗额度；上场残留标识不得永久禁用援军。

### D. 左径战略救援与反攻

1. 有活动战区后按「DEV：直接生成一队战区左径救援」，无需等50%抽签。若无合适无人来源星系，应说明未创建。
2. 在远处看行动记录，未侦知的虚拟队不泄露其来源；靠近理论航路或到达目标星系后再观察实体。
3. 实体化后跟随其完成任务，确认不反复换编成；脱战结束立即卸载，不归还精神创伤资产、不扣联盟额度。
4. 正常概率与上限另测：保持同区域多个目标，确认不会每个殖民地各刷2队。反攻独立最多2队。
5. 验证左径对所有危机身份敌对，对联盟友好、其他非危机中立。退出WAR后恢复旧关系，任务不继续无限生成。

### E. 联盟侦察

1. 按「DEV：组织联盟侦察队」。查看实际来源与目标，沿路跟随。
2. 完成现场调查后查人类报告：一处现场、最多三处附近通信汇总；无足够合法邻域时不虚构星系。
3. 队伍返航前就应看到报告。之后队伍被毁不撤销已上传的内容；尚未到达目标不能提前给现场报告。
4. 未发现的敌方设施或伏击不能被虚拟汇总直接揭露。

### F. Je调查与救援（无需等WR随机投放）

1. WAR中进入非Gamma保护的合适星系；Je没有其他代理任务或待会面时，在行动页按「DEV：发起Je战区调查航程」。
2. 正常观察真实出航；快速测试可按「DEV：将Je调查队送抵目标战区」。这个按钮明确传送测试队，不是正常游戏规则。
3. 到达后应出现追兵、求援回执与10日期限。Je联系人和联盟行动页都能找到目标。点击派遣本身绝不能出现死亡或失联抽签。
4. 及时击败追兵：Je携记录实际返港；同一交战重复回调不能重复发放贡献。
5. 另一个测试分支让期限结束；失败抽签只发生一次。可在DEV把失联概率调成100%检验失联。
6. 失联后不显示确认死亡，不自动恢复联系；连续拨号不能触发原有强制接通保证。需要重复测试时使用「DEV：解除本次Je失联状态」。后续正式救援事件未实现。

### G. 新闻衔接与保存

1. 触发相关WR调拨新闻，选择协调支援。事件簿应有联盟入口，调令不再立刻增加防御数值。
2. 同一战区已有援军时，多个入口都应引用已有任务，不复制舰队。
3. 在整备、集结、战斗结束后、返港途中和Je求援期间分别存读档，核对实体、期限、额度和已结算标记。
4. 小屏幕与不同UI缩放下检查TAB按钮是否被遮挡、输入是否穿透、行动页是否截字；这部分离线测试无法证明。
